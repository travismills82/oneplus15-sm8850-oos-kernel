## Current implementation

- F2FS is built into `vmlinux`; its source is under
  `kernel_platform/common/fs/f2fs/`.
- fscrypt and inline-crypt are built in under
  `kernel_platform/common/fs/crypto/`.
- blk-crypto is built in under `kernel_platform/common/block/`.
- device-mapper, including `dm-default-key`, is built in under
  `kernel_platform/common/drivers/md/`.
- UFS crypto is built in under `kernel_platform/common/drivers/ufs/`.
- Canoe uses the Qualcomm UFS/ICE provider in
  `kernel_platform/common/drivers/ufs/host/ufs-qcom.c`; it programs and evicts
  keyslots through the existing Qualcomm ICE interfaces.

The qualified fscrypt interface already supports multi-device inline
encryption through `fscrypt_operations.get_devices`.  It currently allocates
the returned block-device pointer array dynamically.  Therefore the later
allocation-free fix for CVE-2026-68147 is applicable, but it is not a simple
missing callback addition: it changes that callback contract and requires an
Android generation-5 KABI-preserving adaptation.

## Source ancestry

The qualified common tree contains the complete individually replayed ACK
history through Linux 6.12.35 plus downstream OnePlus/OxygenOS compatibility
work.  The official Android LTS 6.12.35 merge used as the upstream comparison
anchor is `8cb2595f9383` and the corresponding Linux stable version commit is
`783cd2c3dca8b6c434e955b84c20c8940588dc68`.

The F2FS tree differs from the generic Android 6.12.35 tree because this
repository retains OnePlus/Android behavior.  Backports must therefore be
applied commit-by-commit and conflicts resolved semantically; copying a newer
F2FS directory would discard that contract.

The qualified ancestry contains nine earlier downstream F2FS security commits
covering the atomic-inode GC lifetime UAF, invalid-context `vm_unmap_ram()`,
dnode and device-path bounds checks, compression and inode lifetime fixes, and
corrupted-NID validation.  Direct comparison of the qualified tree's final
files showed that later ACK replay/reconciliation no longer retained those
functional changes.  An ancestor commit is therefore not treated as proof
that a fix is present.  The modernization reapplies the authoritative Linux
6.12 stable versions only where the final source state lacks the fix.

## Disk-format and userspace-tool baseline

No proposed change is allowed to add an incompat feature, alter checkpoint,
NAT/SIT, compression, or encryption-policy disk formats, or require a newer
`fsck.f2fs`, `mkfs.f2fs`, `dump.f2fs`, `resize.f2fs`, or `sload.f2fs`.
Selected ordinary bug fixes must record `USERSPACE TOOLS IMPACT: NONE` and
`REFORMAT REQUIRED: NO`.
