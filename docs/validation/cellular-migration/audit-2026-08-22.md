## Result

The physically working closure contains exactly 27 vendor-DLKM modules. All
27 were present in the retained qualified boot capture, and all 27 module
binaries in the combined BT046/NFC102 vendor tree are byte-identical to the
OxygenOS 16.0.9.400(EX01) stock binaries. The full per-module evidence is in
[current-cellular-closure.tsv](current-cellular-closure.tsv); its symbol-level
provider graph is in [dependency-edges.tsv](dependency-edges.tsv).

This audit identifies one genuinely isolated first source-ownership batch:
`rmnet_sch.ko`. It is a leaf qdisc module, exports no API consumed by another
module, has no module dependency or soft dependency, and its nine versioned
imports (including `module_layout`) all resolve from the frozen Image. The
`.097` to `.102` comparison changes only its Bazel definition, not its runtime
C source. Batch 01 therefore tests the current `.097` source build and signing
delivery contract; it does **not** claim a `.102` feature upgrade.

boundary.

## Current generations versus `.102`

The active source families are dataipa `.078`, datarmnet `.078`, and
datarmnet-ext `.097`. The newer same-SM8850 snapshot reaches `.102` and changes
24 files (358 insertions, 162 deletions). See
[newer-102-delta.tsv](newer-102-delta.tsv).

No change in this snapshot is proven to be a security fix from available
source provenance. The useful changes are correctness and resilience work:

- GSI registration/re-registration lifecycle and already-enabled detection.
- IPA SSR allocation retry, firmware-load, filter/route cleanup, and error
  handling.
- IPA header/proc-context relationship cleanup.
- IPA v5.5 low-latency routing and packet-init handling.
- RMNET QMAP priority behavior when the low-latency IPA pipe is unavailable.

The `.102` provider side is high-risk: it adds exported
`gsi_status_enabled()` and adds `pkt_ex_init_valid` to `struct ipa_tx_meta`.
Those changes can alter source/module contracts even if the frozen external
ABI report does not describe all DDK consumers. They belong to Batches C/D,
not Batch 01. The newer snapshot also does not contain the separate upstream
RMNET MAP ingress packet-length validation fix and must not be credited with
that security backport.

## Mandatory gates for every future batch

The release-contract architecture 2 guard must preserve the frozen g6744
kernel release only after proving identical `.config`, `Module.symvers`, Image
contract, exported CRCs, ABI/KMI reports, and signing trust. Vendor source
generation is recorded separately.

The system-DLKM load contract remains mandatory: 46 entries, `wwan.ko` at
entry 21, zero missing entries, and zero stale built-in entries. A package that
drops `wwan.ko` is rejected before flashing.

Static success is not physical success. Every batch still requires HOME/IN
SERVICE registration, RMNET IPv4/IPv6, default routes, IP and DNS, normal data
call setup, airplane-mode recovery, bidirectional Wi-Fi handoff,
suspend/resume, reboot, and hotspot/client traffic when equipment exists.

## Recommendation

Proceed only with Batch 01 (`rmnet_sch.ko`) as the first physical migration
candidate. Its expected payload delta is vendor-DLKM only and exactly one
module. Boot, system-DLKM, vendor boot, VBMeta, WLAN053, BT046, NFC102, and the
other 26 stock cellular modules remain byte-for-byte frozen. Do not import
`.102` in that experiment.
