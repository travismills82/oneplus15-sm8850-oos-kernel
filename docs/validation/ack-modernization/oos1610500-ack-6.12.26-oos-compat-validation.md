# OOS 16.0.10.500 ACK 6.12.26 compatibility validation

## Decision

**PASS — ACK 6.12.26 OOS COMPATIBILITY STATIC AND PHYSICAL VALIDATION**

This supersedes only the static-blocker decision in
`oos1610500-ack-6.12.26-static-validation.md`.  The exact 6.12.26 interval,
the original failure evidence, and the immutable stock payload contract remain
unchanged.  Static remediation itself performed no device write.  The later
controlled physical test wrote only `boot_a`; no stock supporting partition
was written.  No source commit, push, tag, or `main` update was made.

The exact staged boot was subsequently tested on the physical CPH2747.  It
completed two clean Android boots, existing encrypted user 0 reached
`RUNNING_UNLOCKED` on both boots, and no `init_user0_failed` result occurred.
The complete physical record is
`../firmware-16.0.10.500/oos1610500-ack-6.12.26-physical-validation-2026-09-01.md`.

## Real binary-layout compatibility

### `struct request`

Exact DWARF/BTF layout comparison:

| Property | Qualified 6.12.25 | Plain 6.12.26 | Compatibility candidate |
|---|---:|---:|---:|
| `sizeof(struct request)` | 288 | 280 | 288 |
| `write_hint` offset | 144 | removed | 144 |
| `ioprio` offset | 146 | removed | 146 |
| members after `ioprio` | qualified offsets | shifted by -8 | qualified offsets |

The fields are real storage, not padding and not a gendwarfksyms fiction.
When the first bio is attached, the compatibility values mirror
`bi_write_hint` and `bio_prio()`.  Request cloning copies both values.  Native
6.12.26 internal reads continue to use the upstream bio-based accessors, so
the stable update's corrected internal behavior is retained.

Allocation/reuse begins from the normal zeroed request state.  First-bio
attachment, bio merge, request merge, clone, requeue, completion, reuse,
flush, passthrough, and no-bio paths were reviewed against the 6.12.25 and
6.12.26 implementations.  The mirrors preserve the old externally observable
values without restoring removed native internal reads.

Restoring the exact layout removed 186 of the 208 initial stock-module CRC
mismatch edges, including the broad block/SCSI/UFS/ZRAM and Rust Binder type
closures.

### xHCI sideband contract

Plain 6.12.26 replaced `last_td_was_short` at offset 88 with
`old_trb_comp_code`.  The compatibility candidate restores the qualified bool
at offset 88 and stores the new completion code in the already existing
Android KABI reserve at offset 104.  The event path mirrors the bool and uses
the reserved value for the complete 6.12.26 spurious-completion fix.

```text
qualified xhci_ring: size 120, last_td_was_short offset 88, reserve 104
candidate xhci_ring: size 120, last_td_was_short offset 88, reserve 104
```

This removed all 18 `snd_usb_audio_qmi` sideband CRC edges without discarding
the stable fix.

### PCI MSI type visibility

The remaining four `pci_msm_drv` edges were caused solely by newly visible,
but layout-identical, `irq_domain` and `device_node` definitions in the MSI
provider translation unit.  Their physical sizes, members, callback
prototypes, and enum values were unchanged.  Narrow
`ANDROID_KABI_DECLONLY()` rules restore the qualified declaration-only type
visibility; they do not hide a runtime layout change.

### Additional enforced-ABI adaptations

The common enforced ABI comparison also required these source-compatible
ports even though they were not among the 208 stock import edges:

- `typec_port` remains 1,104 bytes.  The new 6.12.26 partner-link mutex is
  heap allocated and its pointer occupies the existing KABI reserve at offset
  1,096; allocation, initialization, all lock sites, error cleanup, and final
  release retain the new locking behavior.
- `PERR_REMOTE` retains value 10 as a macro without extending the frozen
  internal cpuset enum.
- `crypto_null.c` retains the qualified `linux/mm.h` type visibility while
  also keeping the new 6.12.26 spinlock include and synchronization fix.
- `gpiolib_internal_headers` restores the narrow DDK header target required
  by the pinned Oplus GPIO module build; it has no target-runtime behavior.

The complete initial 208-edge inventory is
`oos1610500-61226-stock-module-abi-blockers.tsv`.  Strategy codes in that file
mean:

| Code | Resolution |
|---|---|
| `REQ_MIRROR` | real qualified request fields and bio-derived semantic mirrors |
| `XHCI_RESERVE` | old bool at offset 88; new completion code in reserve 104 |
| `PCI_DECLONLY` | narrow visibility-only KABI rule after exact layout proof |

## Static and physical FBE/storage result

The exact 6.12.26 FBE/storage interval and the compatibility changes were
reviewed for block, bio, blk-mq, I/O priority, SCSI, UFS, runtime PM,
blk-crypto, ICE, device mapper, fscrypt, F2FS, keyrings, crypto, and OEM vendor
hooks.  Effective FBE/storage configuration is unchanged, native 6.12.26
bio-based request logic remains active, the full stock module closure passes,
and the boot-container contract passes.  Static FBE result: **PASS**.

The controlled physical test wrote only `boot_a` after a dry run and two
independent, hash-verified backups.  Recovery read-back and both Android
read-backs matched the staged image exactly.  Existing encrypted user 0,
metadata encryption, stock DLKM mounts, and the complete radio path remained
healthy through two boots and five deep-idle/resume cycles.  No rollback was
required; the qualified 6.12.25 boot remains preserved locally.
