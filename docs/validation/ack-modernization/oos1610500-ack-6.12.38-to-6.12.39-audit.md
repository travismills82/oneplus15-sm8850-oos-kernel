# OxygenOS 16.0.10.500 ACK 6.12.38 to 6.12.39 audit

## Scope and boundary

This experiment starts from the exact published ACK 6.12.38 boot-qualified
repository state at `e73f86fd0ae35418eb24996540fa81173fb5505b`.
The kernel-producing source in that ancestry is
`f7d1832aa532bf848f5565b1ea6caf8b196d579a`; its physically tested boot
image has SHA-256
`c22a18287f11f90a8cadc5efa6a307b4072d1e4b89b8d432f8c3b559334ae6b6`.

Android Common does not publish an `android16-6.12.39_r00` tag.  The exact
completed ACK/LTS boundary was therefore taken from the official merge and
its Linux-stable parent, without inventing a release tag:

| Item | Value |
|---|---|
| Qualified parent ACK commit | `842eca537f36c62ec7a815c19ddfd250e7a275c3` (`android16-6.12.38_r00`) |
| Official ACK/LTS merge | `8eba32b6565d4041bd6fd4530b1b62fe7a45f6f1` (`Merge 6.12.39 into android16-6.12-lts`) |
| Complete Linux-stable parent | `cdf264c0a5906063a0e2b750d420d77cb992446d` (`Linux 6.12.39`) |
| Android `.39` KABI repair | `4a5ce5aeeca24b349f541116f022e80532bcad76` (`Revert "drm/framebuffer: Acquire internal references on GEM handles"`) |
| Published `.39` Android tag | none |
| Version | `6.12.39` |
| ACK branch | `android16-6.12-lts` |
| KMI generation | `5` |

The complete `.38` to `.39` Linux-stable interval contains 167 non-merge
commits.  All were audited in order.  Android Common then immediately applied
`4a5ce5aeeca2` on the `.39` LTS branch because the stable interval's
`drm_framebuffer.internal_flags` addition broke the Android kernel ABI.  That
authoritative Android repair is also preserved as its own commit, making 168
official records in this audit.  Of those, 164 are represented by individual
new commits in this experiment, three complete fixes were already present in
the qualified ancestry, and one older eventpoll fix was superseded by a later,
more complete eventpoll lifetime/RCU security series already carried by the
qualified base.  No 6.12.40 or later commit was imported.  The complete
disposition and upstream-to-local mapping are recorded in
`oos1610500-ack-6.12.39-commits.tsv`.

## Reconciliation decisions

Three official commits triggered Git directory-location conflicts because the
official ACK repository has the kernel at its root while this repository keeps
it under `kernel_platform/common`.  Each was applied at the corresponding
monorepo-prefixed path without changing its functional content:

1. `fc3a8a5e8f8e` added the Intel SOF function-topology helper and Makefile
   entry.
2. `92ed107cd26d` added the maple-tree/xarray GDB helpers and updated the GDB
   interrupt helper.
3. `febc0b5dbabd` added the null/error-pointer guard to
   `lib/alloc_tag.c`.

The following official patches produced no source delta and were not
duplicated:

- `f7fe33f629bb`, the scheduler hotplug/migrate-swap fix;
- `0caba66f0073`, the deadline-server runtime-accounting fix;
- `abf3620cba68`, the USB gadget serial TTY-wakeup race fix (already carried
  as `66714489af15`).

`6dee745bd0ae`, the older eventpoll reference-count fix, was not replayed.
The qualified source already contains the later Android/Linux eventpoll file
lifetime and RCU-reader deferral series (`44c867612ae8` and
`c3b68584dbb4`).  Restoring the older intermediate implementation would undo
part of that later security design.

The Linux-stable interval's `065bd940ee0a` DRM framebuffer change added
`internal_flags` in an existing four-byte padding hole.  Although the physical
layout stayed 192 bytes and all later member offsets remained unchanged, the
new visible member changed 191 generation-5 symbol CRCs.  Android Common's
immediate `.39` repair `4a5ce5aeeca2` reverted that commit and explicitly
deferred it until an ABI-safe implementation was available.  This experiment
applies that exact Android repair as local commit `91380ffbe5a1`; it does not
invent a CRC suppression or update the ABI reference.

## Functional, storage, and configuration review

The resulting interval changes 172 common-kernel files.  The device-relevant
areas include arm64 correctness, Bluetooth, wireless regulatory/channel
handling, USB, scheduler, crypto hardening, and general stable fixes.  The
block-related source changes are limited to NBD and ublk; the device-mapper
changes are limited to MD RAID/bitmap code.

The interval does not change common F2FS, fscrypt, blk-crypto,
dm-default-key, dm-crypt, SCSI/UFS crypto, Qualcomm ICE, the Canoe device tree,
the arm64 GKI defconfig, module-signing policy, trusted keys, ABI definitions,
or KMI symbol lists.  Its Kconfig changes are confined to x86, a generic IRQ
selection dependency, and Intel audio.  Existing encrypted user0 remains a
mandatory future physical oracle; this source audit does not call the build
physically qualified.

No stock supporting payload is modified.  The candidate remains a boot-only
experiment with the exact qualified OxygenOS 16.0.10.500 stock
`system_dlkm`, `vendor_dlkm`, `vendor_boot`, DTBO, and VBMeta.  No ABI/KMI,
MODVERSIONS, signature, CRC, or protected-export check is weakened.

## Validation plan

The final source must pass the Canoe distribution build, enforced common ABI
comparison, strict KMI check, symtypes build, Canoe device-inclusive ABI dump,
merged-config comparison, SHA-512 module-signature validation, retained stock
module provider oracle, and Android-v4/AVB boot-container validation.  Build
results and artifact hashes are recorded separately in the ACK 6.12.39 static
validation report.
