# OOS 16.0.10.500 ACK 6.12.26 static validation

## Decision

**BLOCKED — 6.12.26 STATIC MODULE CONTRACT FAILURE**

This is a controlled, boot-only experiment from the physically qualified
6.12.25 checkpoint.  It does not produce a flashable `boot.img` and has not
been flashed.  `system_dlkm`, `vendor_dlkm`, `vendor_boot`, DTBO, VBMeta,
userdata, and metadata were not modified.

## Configuration result

The first configuration action rejected a stale explicit line:

```text
# CONFIG_UBSAN_SIGNED_WRAP is not set
```

Official commit `984830d902fbd1935872f57d5a23eedaa696bbc7` removes the
`default UBSAN` clause for that symbol.  The generated candidate `.config`
still resolves `CONFIG_UBSAN_SIGNED_WRAP=n`; removing only the now-redundant
arm64 defconfig line made `savedefconfig` reproducible.  No FBE, storage, or
module-security configuration was changed.

The generated candidate retains:

```text
CONFIG_MODULE_SIG=y
CONFIG_MODULE_SIG_ALL=y
CONFIG_MODULE_SIG_PROTECT=y
CONFIG_MODVERSIONS=y
CONFIG_GENDWARFKSYMS=y
CONFIG_MODULE_SIG_SHA512=y

```

## Build failure

Command:

```sh
cd kernel_platform
tools/bazel build //common:kernel_aarch64
```

The target compiled `vmlinux`, `Image`, and `Module.symvers`, then failed in
`modules_install`.  The exact blocker is the official first 6.12.26 commit:

```text
e62c31802dcc76f89df73f4b18cffedb8
module: sign with sha512 instead of sha1 by default
```

The OnePlus build environment links `scripts/sign-file` to the hermetic
`libcrypto-host.so`, a BoringSSL-compatible OpenSSL 1.1.1 implementation.  It
does not provide CMS signing and reports:

```text
sign-file: OpenSSL 1.1.1 (compatible; BoringSSL) only supports SHA1 signing
```

The candidate truthfully selects SHA-512, so downgrading the hash, disabling
module signing, disabling `CONFIG_MODULE_SIG_ALL`, or using an unpinned host
crypto library would violate this experiment's security and reproducibility
contract.  No such workaround was applied.

The retained, unqualified intermediate artifacts are only evidence for the
read-only module audit below; they are not release artifacts:

The strict ABI and KMI Bazel targets were not run: their required

not a pass and must not be represented as one.

## Read-only stock-module contract audit

The retained `Module.symvers` was audited against the exact 1,020 extracted
OOS 16.0.10.500 module binaries and stock load lists.  This does not rescue
the failed build; it establishes whether a boot-only candidate could safely
load the immutable module universe.

| Gate | Result |
|---|---:|
| Physical module files checked | 1,020 |
| Compatible modules | 962 |
| Dormant modules | 36 |
| Active blockers | 22 |
| Unresolved imports | 0 |
| Symbol CRC mismatches | 208 |
| Protected-export failures | 0 |
| Signature/trust failures | 0 |
| Structural-provider contract | FAIL |

The 22 active blockers cover these required consumers:

```text
system_dlkm: rust_binder, virtio_blk, zram
vendor_boot: cqhci, sg, ufs_oplus_dbg, ufs_qcom, ufshcd_crypto_qti,
             zram, and four oplus_bsp_dfr recovery modules
vendor_dlkm: zram, snd_usb_audio_qmi, pci_msm_drv, and the same four
             oplus_bsp_dfr modules
```

`rust_binder.ko` has 166 imports: 150 CRC matches, 16 CRC mismatches, and no
unresolved symbols.  The mismatches include its exported Rust wrappers for
`Page::read_raw`, `Task::{euid,policy,current}`, and helpers for credentials,
files, `mm_struct`, and VMA lookup.  This is not hidden: the module cannot
securely load against the candidate CRC contract.

The storage consumers show a real module-observable ABI change.  Official
6.12.26 commits `3e12e8c273ebcf346bfafdf7066764324912b070` and
`ed7535b141161f71c5f03a2bce361a0ca842c166` remove `request.write_hint` and
`request.ioprio`, respectively.  Candidate DWARF reports `struct request` at
280 bytes.  The stock `virtio_blk`, ZRAM, SCSI, UFS, CQHCI, and Oplus recovery
modules consequently have block/UFS provider CRC mismatches.  Examples
include `blk_mq_alloc_request`, `blk_mq_free_request`, `blk_execute_rq`,
`__blk_alloc_disk`, `device_add_disk`, `ufshcd_runtime_resume`, and
`devm_blk_crypto_profile_init`.

These are genuine ABI gates, not an error that may be hidden by changing
vermagic, CRC values, module signatures, protected exports, or the displayed
kernel version.

## Required next action

Do not flash this candidate and do not begin 6.12.27.  A later controlled
attempt must first obtain a reproducible, approved generation-5 host crypto
toolchain capable of SHA-512 CMS module signing, then address the documented
stock-module ABI migration using a justified Android KABI mechanism or matching
module set.  Neither action is authorized by this failed boot-only experiment.
