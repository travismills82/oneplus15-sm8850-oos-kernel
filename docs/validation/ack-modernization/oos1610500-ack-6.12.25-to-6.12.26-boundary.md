# OOS 16.0.10.500 ACK 6.12.25 to 6.12.26 boundary

## Scope and immutable parent

This is a controlled, one-sublevel experiment only. Its parent is the
physically qualified OxygenOS 16.0.10.500 checkpoint:

- branch: `feature/oos1610500-ack-6.12.25-qualified`;
- parent HEAD: `e32d8f9502d7b03c0ffa49e584bf96f6d2bc9000`;
- parent tag: `oos16.0.10.500-ack-6.12.25-qualified`;
- parent kernel: `6.12.25-android16-5-o-g48618bcd6275-4k`.

The experiment branch is `experiment/oos1610500-ack-6.12.26`. It contains
only the Android Common Kernel delta described here plus this audit. It does
not advance to 6.12.27, later stable releases, or a later KMI generation.
It does not create, alter, or package `system_dlkm`, `vendor_dlkm`,
`vendor_boot`, DTBO, VBMeta, userdata, or metadata.

## Three-way integration result

The merge base was official 6.12.25, with the qualified OnePlus common tree as
the local side and official 6.12.26 as the upstream side. There was one real
content conflict:

| File | Upstream intent retained | Qualified local intent retained | Resolution |
|---|---|---|---|
| `drivers/usb/host/xhci.h` | `old_trb_comp_code` replaces the retired boolean and `xhci_enable_interrupter()` is declared | Existing Android KABI reserves following `trb_address_map` | Keep both; no reserve was consumed or removed |

All other paths merged three-way without an unresolved conflict. The
resolution is deliberately not an `ours` or `theirs` replacement.

## Struct request and storage/FBE focus

Two official 6.12.26 commits change `struct request` directly:

| Commit | Change | Required disposition |
|---|---|---|
| `3e12e8c273ebcf346bfafdf7066764324912b070` | removes `request.write_hint` | retained; audit actual ABI/module impact |
| `ed7535b141161f71c5f03a2bce361a0ca842c166` | removes `request.ioprio` | retained; audit actual ABI/module impact |

The source-level change removes the two members from `include/linux/blk-mq.h`.
Consequently, a 288-to-280-byte `struct request` change is plausible and is a
hard static gate, not a reason to reintroduce declarations or change CRCs.
Downstream source searches found no direct OnePlus/Qualcomm `->write_hint` or
`->ioprio` access; that does not prove compatibility of the stock binary
module universe. The build ABI reports, gendwarfksyms output, and the
1,020-module import/CRC/provider audit remain authoritative.

The later AF_XDP commit `65d3c570614b` is **not** an ancestor of the final
6.12.26 commit and is excluded from this experiment.

The focused review also covers block/bio/blk-mq, I/O priority, SCSI/UFS,
runtime PM, blk-crypto, ICE, device mapper, fscrypt, F2FS, keyrings, crypto,
and Android/Qualcomm vendor-hook paths. No FBE behavior is modified by this
experiment.

## B01-B08 and local compatibility preservation

The 6.12.26 range intersects the qualified B01-B08 runtime path set only at
`kernel/bpf/hashtab.c`; that overlap is explicitly marked in the per-commit
audit and must retain the existing qualified behavior. No other Binder, USB
UDC, eventpoll, AF_UNIX, IPv6 MLD, AF_PACKET, or quota2 path is in the range.

Existing module-signing, MODVERSIONS, gendwarfksyms, protected-export,
ABI/KMI, stock module trust, and stock `modules.load` policy remain enabled
and are validation gates rather than adjustable workarounds.

## Toolchain and pending gates

The candidate will use the repository-declared Kleaf Android LLVM toolchain
selected by `//common:kernel_aarch64`; its resolved version/path will be
recorded with the build result. No build artifact, boot image, or physical
test is authorized by this boundary record alone.

Before a boot image may be assembled, the exact candidate must pass generated
configuration comparison, FBE/storage audit, enforced ABI/KMI checks, and the
full 1,020-module stock contract including `rust_binder.ko`. A genuine
layout/provider incompatibility is a stop condition: do not flash.
