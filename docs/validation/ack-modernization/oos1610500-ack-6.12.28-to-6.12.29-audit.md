# OOS 16.0.10.500 ACK 6.12.28 to 6.12.29 audit

## Scope and parent

This controlled update starts from repository commit
`a767173a43389f12ad137c0049048ebea8656869` on the published
`oos16.0.10.500-ack-6.12.28-candidate` lineage and advances only the
Android Common portion from Linux 6.12.28 to Linux 6.12.29. The parent is a
statically validated test candidate; the repository does not contain a
physical-qualification record for it.

No source from Linux 6.12.30 or a later sublevel is included. This update does
not change `system_dlkm`, `vendor_dlkm`, `vendor_boot`, DTBO, VBMeta,
userdata, metadata, the stock module load policy, or the selected OnePlus and
Qualcomm source revisions.

## Android KABI repair

The official stable interval includes `2910019b04eb` (`mm: vmalloc: support
more granular vrealloc() sizing`), which adds `requested_size` in the middle
of module-visible `struct vm_struct`. The Oplus
`vendor/oplus/kernel/mm/memleak_detect/vmalloc_track.c` consumer makes that a
real binary-layout contract, not type-visibility noise.

Android Common later supplied the authoritative generation-5 repair
`8c70afee5a66782e43db17436fd8bc7011cd4fc3`, explicitly reverting the change
because it breaks Android KABI. It is preserved as separate repository commit
`5f4d1ccb2b227dcbcd6ef11ca9b27f8bcaf3f6f8`. No CRC, vermagic, or DWARF type
string was forged.

## Storage and FBE review

The only direct device-mapper encryption-path change in the interval is
`b32411f0459d`, which ensures `dm_put_live_table()` runs when
`dm_get_live_table()` returns null during keyslot eviction. It is a balanced
SRCU cleanup fix and does not change key identity, inline-encryption policy,
or the module ABI.

The remaining storage changes cover EROFS file I/O, loop-device discard and
locking, OCFS2 recovery, unmount ordering, and an NVMe firmware-update state
transition. The interval contains no F2FS, fscrypt, dm-default-key,
blk-crypto API, Qualcomm ICE, Canoe UFS, or keyring policy change. The final
generated FBE/storage configuration is identical to 6.12.28, and the complete
stock module CRC/import contract passes. Existing encrypted user0 remains a
mandatory physical gate.
