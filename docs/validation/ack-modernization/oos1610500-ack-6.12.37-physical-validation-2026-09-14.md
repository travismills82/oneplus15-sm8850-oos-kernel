oracle, two clean Android boots, critical radio/module checks, and repository

authorized promotion to `main` and a stable GitHub release.

## TWRP encrypted-data oracle

TWRP ran the candidate kernel and passed:

- PIN decryption and `User 0 Decrypted Successfully`;
- metadata-encrypted userdata mapper creation;
- F2FS `/data` read-write mount with `inlinecrypt`;
- access to existing `/data/media/0` content;
- empty persistent pstore.

One earlier recovery-log failure came from invoking `twrp decrypt --help`,
which TWRP interpreted as a decryption attempt.  The subsequent real PIN
operation succeeded; that command-line misuse is not a candidate failure.

## Android and subsystem validation

Two clean Android boots completed with:

- `sys.boot_completed=1`;
- user 0 `RUNNING_UNLOCKED` and CE available;
- F2FS `/data` read-write with `inlinecrypt`;
- stock `system_dlkm` EROFS and stock `vendor_dlkm` mounted read-only;
- 6135 MHz WPA3-SAE 802.11ax WLAN and Internet traffic;
- cellular registration plus RMNET IPv4/IPv6, direct-IP, and DNS traffic;
- Bluetooth initialized and on, including an existing wearable connection;
- ZRAM/ZSMALLOC active;
- Rust Binder and the critical UFS/ICE, WLAN/CNSS, Bluetooth, and RMNET
  module chains loaded;
- camera, audio, fingerprint, NFC, display, touch, and USB framework/HAL
  services initialized;
- no persistent pstore record.

The runtime module-name set contained 665 modules and matched the immediately
qualified 6.12.36 baseline.  Fatal scans found no panic, oops, watchdog reset,
unknown symbol, version/CRC disagreement, invalid module format, signature
failure, protected-export failure, `init_user0_failed`,
`bootstrap-apexd-failed`, or F2FS/dm-default-key/blk-crypto failure.
