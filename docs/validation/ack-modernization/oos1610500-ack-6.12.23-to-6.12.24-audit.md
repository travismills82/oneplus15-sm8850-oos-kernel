## Reviewed Android integration

### cgroup `css_killed`

Stable commit `cdb6e724e7c5713d13c5ad3340e9d71c3dd8c9fb` adds the
`css_killed` callback. Adding it directly changes the frozen
`struct cgroup_subsys` layout. The reviewed Android adaptation retains
`ANDROID_BACKPORT_RESERVE(1)` exactly and stores/loads the typed callback
through that existing pointer-sized slot. The callback behavior is present
without changing the reserved field name, structure size, or offsets.

### `struct sock` lockdep owner

Stable commit `5f7f6abd92b6c8dc8f19625ef93c3a18549ede04` conflicts with
Android KABI reserve placement. The resolution retains the conditional
`sk_owner` field and its set/clear/put lifetime operations while preserving all
eight `ANDROID_KABI_RESERVE()` entries and `ANDROID_OEM_DATA(1)`.

### Futex selftest

The r53 selftest already contains the corrected would-block result from
`206d0df7b6a52daa6a9dcb326b243bbce389344c` and additionally treats
`ENOSYS` as an Android skip. No duplicate patch is applied. This is selftest
behavior, not a runtime futex implementation change.
