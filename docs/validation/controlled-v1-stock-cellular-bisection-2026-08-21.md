# Controlled-v1 stock-cellular bisection — 2026-08-21

## Scope and safety boundary

This experiment keeps the controlled-v1 Image fixed and restores the complete
OxygenOS 16.0.9.400(EX01) vendor-side cellular packet-data closure to exact
stock binaries. It does not change WLAN source versions, `CONFIG_CFG80211`,
module-signature enforcement, MODVERSIONS, protected exports, `vendor_boot`,
or VBMeta. No image documented here has been flashed.

Slot `_b` currently runs the restored r7 stock-DLKM baseline. Slot `_a` is
marked unbootable and is not a fallback. A later physical test requires a
fresh, readable, SHA-256-verified TWRP backup before any write.

## Pass/fail evidence

The failed controlled-v1 and restored r7 captures agree through the observable
kernel-side IPA/GSI/RMNET initialization sequence:

- IPA readiness callback registration;
- GSI device registration;
- RMNET control, low-latency, and netdev PM-client registration;
- `rmnet_data1` registration to IPA;
- Peach-v2's IPA-ready callback and TX-buffer mapping.

The first proven module-delivery divergence is `wwan`: restored r7 has it in
`/proc/modules`, while the failed stack does not. Stock system-DLKM
`modules.load` explicitly requests `wwan.ko`; the failed controlled image
contains a matching controlled `wwan.ko` but shipped an empty `modules.load`.

The first meaningful functional divergence is then the RIL `SETUP_DATA_CALL`
response. Restored r7 receives `NONE(0x0)` with an RMNET interface, address,
DNS, and gateway. Controlled-v1 receives `OEM_DCFAILCAUSE_4(0x1004)` with
`cid=-1` and empty interface/address/DNS/gateway fields. No authoritative
mapping for that vendor code exists in the available kernel/vendor source;
unrelated numeric uses of `0x1004` are not a definition of the RIL failure.

The chronological comparison is in
`docs/validation/cellular-pass-fail-timeline.tsv`. Module hash, signer,
vermagic, load-position, and dependency evidence is generated by
`tools/audit-controlled-v1-cellular-bisection.py`.

## Cellular data closure

Walking real `depends=` metadata backward from GSI/IPA/RMNET/data roots finds
63 modules across `vendor_boot`, `vendor_dlkm`, and `system_dlkm`. The full
table is `docs/validation/cellular-data-closure.tsv`.

Candidate A preserves all 27 vendor-DLKM members of this closure byte-for-byte
from stock. Across the original candidate partitions, 62 of 63 closure members
remain exact stock; the sole binary difference is controlled modular
`wwan.ko`. Its load-policy correction is deliberately isolated by TEST 2
before Candidate A can be tested.

The prior failed vendor image had replaced or re-signed IPA/IPAM/RMNET-related
modules. Candidate A restores those exact stock binaries rather than assuming
that clean symbol/CRC checks guarantee behavioral equivalence.
