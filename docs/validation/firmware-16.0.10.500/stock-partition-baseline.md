# OxygenOS 16.0.10.500 firmware compatibility baseline

## Scope and conclusion

This record establishes the native CPH2747/Canoe contract for
`CPH2747_16.0.10.500(EX01)` and isolates the first incompatible layer of the
previously qualified ACK 6.12.24 stack. No source was rebuilt, `vendor_boot`,
VBMeta, and slot metadata were not written, and Stage 2/Stage 3 were not
prepared.

The first bad layer is **Stage 1: ACK 6.12.24 boot/kernel with exact stock
16.0.10.500 DLKMs**. Static module compatibility passed, but Android entered
Rescue Party recovery with `--reason=init_user0_failed`. This is a
boot/kernel/init compatibility boundary, not a system-DLKM or vendor-DLKM
isolation result.

## Stage 1 physical isolation

Only `boot_a` was changed:

- ACK boot: `3ceb46491d029586af1a6dc494b5baf4ddb973ad0c065c0960e4ed307d9d40b9`
- stock system_dlkm: `18f530dcb0e46dc81ede00e18ac4e9b39faf6564fb067f04af9a912d87fd6dd7`
- stock vendor_dlkm: `157db23ccfa516c7904d4e87614f62c3c99c2dcbb93cc3fc8ccd3388c2cc793f`

TWRP dry-run, backup, capacity, input hash, write, and read-back checks passed.
The DLKM read-back hashes remained stock. Android did not complete; after 85
seconds ADB returned in TWRP recovery. `/tmp/recovery.log` records:

```text
boot command: boot-recovery
Android Rescue Party trigger!
'--reason=init_user0_failed'
```

The exact stock `boot_a` was then restored and verified. Stock Android booted
in 41 seconds with the expected 16.0.10.500 display ID and stock kernel.

## Decision

**FAIL — ACK 6.12.24 BOOT/KERNEL/INIT CONTRACT IS INCOMPATIBLE WITH OOS
16.0.10.500 AS CURRENTLY BUILT.**

Stage 2 and Stage 3 are stopped. No adapted DLKM should be prepared until the
`init_user0_failed` boot/kernel contract is isolated without changing the
firmware-native DLKMs.
