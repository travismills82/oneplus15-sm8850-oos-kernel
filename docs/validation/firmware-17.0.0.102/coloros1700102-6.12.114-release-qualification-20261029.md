# ColorOS 17.0.0.102: Linux 6.12.114 release qualification

## Qualification scope and decision

**PASS: physical and exact-stock-module qualification for the firmware-bound
boot-only boot/stability release scope.**

The owner requested qualification and confirmed the remaining interactive
hardware functions on the exact retained candidate. This completes the
physical scope used by the preceding ColorOS .102 stable release. No new
runtime incompatibility was identified by the additional consumer/layout
audits below.

This is not an unconditional all-gates-PASS, official GKI certification, or a
claim that every upstream .114 fix is incorporated. The enforced common ABI
comparison returns 4 against the older .601 reference, and a substantive
conntrack omission remains tracked. Those limitations must accompany any
release. They are not relabeled PASS or silently suppressed.

No source commit, tag, main update, push, installer publication or GitHub
release is authorized by this qualification record. Those are separate
operations. Preserve the exact tested boot bytes; do not rebuild for a clean
release name or changed commit identifier.

## Normal enforced ABI comparison: actual result and reconciliation

The distribution command cannot complete because bundled selftests require
the absent libcap/libcap-ng inputs. Source audit identified and ran the same
normal executable the wrapper invokes:

```sh
tools/bazel run //common:kernel_aarch64_abi_diff
```

It uses the checked-in common/gki/aarch64/abi.stg, normal filtered common dump
and kmi_enforced=True, and returns the real stgdiff exit status. No checker,
reference, CRC or enforcement was modified. **Result: exit 4, differences.**

The reference remains SHA256
`99ae68d5f6f6fa387c4dc8eb2809de8ea4634de517aec269858be1258223bb9e`,
last changed by the OxygenOS .601 reconstruction. The generated common dump
is SHA256 `0aea063f56195b97e0bb2800006dee3afed8bfb688ccf5b8c3600a7033d61bbb`.
The compared vmlinux, symvers and config are byte-identical to the frozen
production candidate: this is not an analysis-variant mix-up.

Reviewed CRC/interface provenance:

- Three Rust and three Tegra CRC differences already exist in qualified
  ColorOS .112 and .113. The only stock imports among them are two arm_smmu
  Tegra providers, both matching the new ColorOS CRCs exactly. The three old
  Rust records have no importers in this 1070-module stock population.
- Seven further CRC differences belong to rebuilt netfs.ko, not vmlinux.
  That rebuilt provider is not deployed; stock netfs.ko remains installed.
  None of those seven exports has an external importer in the stock universe.
- __tty_port_tty_hangup is already present in qualified .113 and .114 with
  the same CRC and QCOM symbol-list entry. Its apparent addition is reference
  age, not a new .114 regression.
- Four GPIO setters genuinely change source return type from void to int.
  Arguments remain x0(pointer)/w1(int); legacy direct callers ignore the new
  return register. All 439 relevant relocations across 68 partition-qualified
  stock consumers are R_AARCH64_CALL26 in text; no indirect/address/data use
  was found. The existing CRC metadata is not alone the compatibility proof.
  This is reviewed one-way source-API evolution, not merely DWARF formatting
  or a guarantee for arbitrary future old function-pointer consumers.

Private-layout audit of the highest-risk real layout changes:

| Root | Actual change | Exact retained-stock boundary finding |
|---|---|---|
| blkg_policy_data | 16 to 32 bytes, old member offsets unchanged | Enabled IOCOST/BFQ policies and allocations are built together; zero retained stock policy/blkg consumers found. SAFE_INTERNAL for this population. |
| folio_queue | 328 to 336 bytes, debug IDs appended at 328/332 | Stock netfs allocates 328-byte objects; built-in iterator/scatterlist code accesses only the unchanged prefix and linked pointers, never the new tail or sizeof-based stride. COMPATIBLE_PREFIX at the actual boundary. |
| xsk_buff_pool | Size remains 256; tail offsets change | No retained stock xp_/xsk_ API consumer or enabled downstream stmmac consumer found. Current core allocator/accesses build together. SAFE_INTERNAL for this population, not universal old-driver compatibility. |

These findings reconcile the most important reported changes with the clean
shipping module contract. They do not turn the enforced result into PASS or
authorize a blanket ABI-reference update. Any reference evolution requires a
separate reviewed authorization. Do not revert stable behavior merely to
match the older firmware reference.
