## One-variable correction

The previous adaptation appended an ignored RCU head to `nf_hook_ops` and
advertised a 40-byte KABI type, but the actual object grew to 56 bytes. This
was unsafe for stock-module arrays traversed by the exported registration
APIs, even though the symbol CRCs matched.

The correction is limited to four files relative to the previous full .114
source state:

- `kernel_platform/common/include/linux/netfilter.h`: remove the added RCU
  field and size/ignore annotations, restoring actual 40-byte object stride.
- `kernel_platform/common/net/netfilter/nf_nat_core.c`: use supported
  `kfree_rcu_mightsleep()` for the two NAT hook-array frees.
- `kernel_platform/common/net/ipv4/netfilter/iptable_nat.c`: use the same
  headless API at both hook-array free sites.
- `kernel_platform/common/net/ipv6/netfilter/ip6table_nat.c`: likewise.

Stable commit `0ab8cfd6547bc73108f534dbf86da2fbaed17ffd`, upstream
`6eda0d771f94267f73f57c94630aa47e90957915`, remains present. Its delayed-free
semantics are retained. The headless API requires sleepable context; all six
sites are registration-error or process-context teardown paths already using
GFP_KERNEL and/or the NAT mutex. Private-object RCU frees remain unchanged.
No CRC, module binary, Kconfig, ABI reference or stable commit is edited.

The first 315-commit midpoint with this mechanism booted and stayed healthy
through 285 seconds: boot complete, unlocked user0, F2FS inlinecrypt, stock
network modules loaded and no targeted fatal/module/hung-task errors. That
result supports this repair but is not qualification of the complete .114.
The implementation here is identical; the midpoint has an additional comment
at one free site, not a code difference.
