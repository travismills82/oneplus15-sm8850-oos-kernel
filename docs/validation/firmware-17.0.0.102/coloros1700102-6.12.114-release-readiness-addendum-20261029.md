AMANDA, IRC, SANE, TFTP and broadcast helpers are also built in. Generic TCP/UDP
conntrack does not by itself create a helper expectation. Local source assigns
helpers from configured templates (nf_conntrack_core.c:1792–1793,
nf_conntrack_helper.c:191–234); xt_CT.c supports explicit helper attachment.
Netfilter netlink configuration requires CAP_NET_ADMIN at nfnetlink.c:661–663.
USER_NS=n narrows a local unprivileged route, but does not prove that remotely
driven helper sessions are unreachable after privileged service configuration.

AOSP Android 16 netd explicitly installs downstream tethering rules assigning
FTP helper to TCP 21 and PPTP helper to TCP 1723 in
`TetherController::setForwardRules()` at lines 714–730. Thus ordinary tethering
can involve privileged service configuration followed by peer-created helper
traffic; it is not valid to dismiss exposure because configuration needs root.
[Android 16 netd source](https://android.googlesource.com/platform/system/netd/+/refs/heads/android16-release/server/TetherController.cpp)

This is a **reference-platform reachability inference**, not proof of exact
ColorOS rules. Saved device evidence does not include complete current
iptables/ip6tables rules, active expectations, or a matching ColorOS netd
implementation analysis. No new device access was performed. Exploitability
on this phone is therefore not demonstrated, but absence of exposure is also
not established.

### Prerequisites and follow-up risk

The final stable fix has no explicit Depends-on trailer. Source/semantic review
still requires a coherent series rather than an isolated clean cherry-pick:

1. Official stable expectation layout contains namespace/helper state absent
   from the current preserved 208-byte downstream type. The change replaces
   timer_list with a 32-bit expiration value and removes nf_ct_remove_expect().
   Preserve lifetime semantics while reviewing actual retained private/type
   consumers; do not force CRCs or restore an unsafe old implementation.
2. The submitted 6.12 backport series used upstream
   `fe97fd540a03034a780224f24b0b2f0e21c9c763` (move PPTP GRE cleanup to GRE
   tracker) and `e3cd138e560764299965fba5ec5240281a7faca2` (NULL-check retrieved
   conntrack extensions). Current source retains the older cleanup/helper
   patterns. These are dependency candidates to reconcile against the final
   stable patch, not authorization to import unrelated changes. The maintainer
   also identified an incorrect success return in the proposed GRE error path.
3. Upstream `4aa63842fc92de1bce59d4709a0d32e718890bb2`, adding/using
   nf_ct_expect_related_pair(), is an important semantic follow-up. With GC,
   unexpect invalidates asynchronously; SIP/H.323 port-pair loops must not
   reinsert still-linked DEAD expectations. **H.323 is enabled here.** The
   stable maintainer explicitly flagged this missing prerequisite/follow-up
   in the earlier submission.
4. Evaluate subsequent DEAD insertion hardening
   `e765c95faa10a8b4e6e9ac7d338eca9662dc56da` and
   `5fc04d4648f4e699e0df7982e37bcdec23daf39c` for the final coherent backport.
   Upstream `322371b09058ad10d0282a0e7ec8eaa764e6aaac` keeps DEAD internal;
   its flag-mask behavior already exists in current nf_conntrack_netlink.c:3048
   via stable `898c917400e857749fe08d58bd8dfd8ab102bd25`. That mask alone
   does not repair the timer/master race.
