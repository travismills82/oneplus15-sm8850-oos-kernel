## Source disposition

Applicable: the qualified source retains the asynchronous expectation timer /
stale-master race. No equivalent lifetime fix was found. Official Linux 6.12
fix `02f7809a19fc88cfd9bc113a4bfe7add6305db39` is the primary porting reference,
with upstream `b8b09dc2bf35a00d4e0556b5d6308c7b917ebda2`; inspected
`7ec786f4230c2a9b2eaf97a2d45368933b49d2b2` is a 7.1 counterpart, not a patch
applied directly to this tree.

The port uses GC and one hash reference instead of timer ownership. A private
slab wrapper stores namespace/zone/creator/tuple/ID/deadline while preserving
the complete public expectation type. Paired insertion and DEAD rejection
cover H.323 and SIP retry semantics. Creator and assignment helper object/
module references protect cached metadata until the final RCU free. Ordinary
module/helper deletion can return EBUSY while those references remain; this is
intentional lifetime protection, not a hidden module load failure. No helper
callback cast, public helper-layout change or new stock DLKM is introduced.

The first build attempt was deliberately interrupted after deeper review found
that old helper-unregister RCU waits alone were insufficient for newly cached
creator pointers. That attempt is not a successful build. Its log is retained
as `production-attempt01-aborted-for-helper-lifetime-review.log`. The source
review explains the corrected reference ownership rather than retaining the
superseded safety claim.
