after its early-boot failure, directed a runtime bisect. This is diagnostic

## DWC3 private-ABI compatibility repair

The first bad commit added a work item, mutex, state, and retry counter directly
to `struct dwc3`. That grew the object from 1,488 to 1,576 bytes and moved
`xhci` from offset 384 to 464, with every later member displaced. The stock
ColorOS `dwc3-msm.ko` directly dereferences this private structure, so its
runtime view no longer matched the built-in DWC3 core despite all exported
symbol CRCs remaining compatible.

The repair keeps the complete stable recovery behavior while moving the new
state into a separately allocated private context. A pointer to that context
uses existing `struct dwc3` Android KABI reserve slot 1. Initialization and
teardown allocate, initialize, cancel, destroy, and free the context through
the normal gadget lifecycle. No callback cast, CRC override, symbol-list
weakening, or stable-fix revert is used.

Only these implementation files contain the repair:

```text
kernel_platform/common/drivers/usb/dwc3/core.h
kernel_platform/common/drivers/usb/dwc3/ep0.c
kernel_platform/common/drivers/usb/dwc3/gadget.c
```

that repaired `struct dwc3` is again 1,488 bytes, `xhci` is again at offset
384, and every pre-existing member retains its #275 offset. Reserve slots 2-4
are unchanged; reserve slot 1 now stores only the recovery-context pointer.
